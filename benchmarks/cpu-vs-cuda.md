# DNN CPU vs CUDA 프로파일링

이 프로젝트의 CUDA 경로는 정상 상태의 두 샘플 처리 시간을 중앙값 기준 `28.464 ms`에서 `22.762 ms`로 20.0% 줄였다. 처리량은 `66.939`에서 `84.183 images/s`로 25.8% 늘었고, 측정 구간의 프로세스 CPU 시간은 91.7% 감소했다.

대신 첫 사이클은 `48.168 ms`에서 `558.402 ms`로 늘고 피크 working set은 약 `546 MiB` 증가했다. p95는 `36.549 ms`에서 `30.184 ms`로 17.4% 줄었다. 작은 모델을 batch 1로 호출하는 현재 구조에서 CUDA의 주된 이점은 반복 추론의 지연 감소와 CPU 여유 확보다.

## 측정 환경

| 항목 | 값 |
|---|---|
| CPU | AMD Ryzen 7 7800X3D, 8C/16T |
| GPU | NVIDIA GeForce RTX 5060 Ti, 16 GiB |
| Driver | 610.88 |
| OS | Windows 11, build 26100 |
| Build | Release, MSVC 19.51, OpenCV 5.0 static |
| CUDA | Toolkit 13.3, cuDNN 9.24, `sm_120`, DNN target FP16 |
| CPU backend | OpenCV classic DNN, 16 threads |

CPU와 CUDA는 같은 CUDA-enabled 실행 파일에서 backend만 바꿨다. 빌드 차이가 아니라 실행 backend 차이를 비교하기 위해서다.

한 사이클은 고정된 두 입력으로 구성했다.

1. `320×240` 얼굴 입력: 표정 모델과 손바닥 검출 경로
2. `262×196` 실제 손 샘플: 손바닥 검출과 21관절 추정 경로

각 backend를 독립 프로세스로 5회 실행했다. 매 실행은 첫 사이클을 따로 측정하고, 10사이클을 워밍업한 뒤 100사이클을 기록했다. 아래 값은 다섯 실행에서 얻은 지표의 중앙값이다. `nvidia-smi` 지표는 100 ms 간격으로 프로세스 실행 구간 전체를 샘플링했다.

## 결과

| 지표 | CPU | CUDA FP16 | 차이 |
|---|---:|---:|---:|
| 모델 로드 | 29.738 ms | 60.546 ms | CUDA 2.04× |
| 첫 사이클 | 48.168 ms | 558.402 ms | CUDA 11.6× |
| 얼굴 경로 p50 | 13.203 ms | 11.428 ms | -13.4% |
| 손 경로 p50 | 15.251 ms | 11.201 ms | -26.6% |
| 사이클 평균 | 29.877 ms | 23.757 ms | -20.5% |
| 사이클 p50 | 28.464 ms | 22.762 ms | -20.0%, 1.25× |
| 사이클 p95 | 36.549 ms | 30.184 ms | -17.4% |
| 처리량 | 66.939 images/s | 84.183 images/s | +25.8% |
| 100사이클 프로세스 CPU 시간 | 30,937.500 ms | 2,578.125 ms | -91.7% |
| 사용 CPU core-equivalent | 10.355 | 1.072 | -89.6% |
| 피크 working set | 223.938 MiB | 770.207 MiB | +546.269 MiB |
| GPU 사용률 평균 | 4.812% | 19.394% | +14.582%p |
| GPU 사용률 최대 | 12% | 26% | +14%p |
| GPU 전력 평균 | 29.877 W | 35.557 W | +5.680 W |

CPU 시간은 모든 스레드의 user+kernel time 합계다. `10.355 core-equivalent`는 측정 구간 동안 논리 코어 약 10.4개가 계속 일한 것과 같은 CPU 시간을 뜻한다. GPU 사용률과 전력은 시스템 전체 값이므로 데스크톱 렌더링을 포함하지만, CPU 실행과 번갈아 측정해 기준선을 함께 남겼다.

실행별 사이클 p50에는 다음과 같은 편차가 있었다.

| Run | CPU | CUDA FP16 | CUDA 변화 |
|---:|---:|---:|---:|
| 1 | 28.464 ms | 22.715 ms | -20.2% |
| 2 | 31.857 ms | 22.621 ms | -29.0% |
| 3 | 29.003 ms | 23.623 ms | -18.5% |
| 4 | 28.050 ms | 24.180 ms | -13.8% |
| 5 | 27.558 ms | 22.762 ms | -17.4% |

CUDA는 다섯 실행 모두에서 p50을 줄였고, 감소 폭은 13.8~29.0%였다. p95도 개선됐지만 얼굴 경로 p95는 CPU `17.150 ms`, CUDA `17.089 ms`로 거의 같고 GPU 평균 사용률은 약 19.4%에 머문다. 측정 결과로 볼 때 작은 tensor의 batch 1 추론에서는 연산량보다 kernel launch, 동기화, CPU 전·후처리의 비중이 큰 것으로 해석할 수 있다.

## 판단

- 웹캠처럼 프로세스가 오래 유지되고 CPU가 얼굴 검출·특징 추출·UI도 처리해야 한다면 CUDA가 유리하다. 추론 지연 감소보다 약 10개 논리 코어에 해당하는 CPU 작업을 GPU로 옮긴 효과가 크다.
- 단일 이미지 한 장만 처리하고 종료한다면 CPU가 빠르다. 모델 로드와 첫 사이클을 합친 초기 비용은 CPU `77.906 ms`, CUDA `618.948 ms`다.
- 정상 상태 p50 절감량으로 초기 비용 차이를 회수하려면 약 95 benchmark cycles가 필요하다. 장시간 실행에서는 상쇄되지만 짧은 명령에서는 상쇄되지 않는다.
- 전체 p95는 줄었지만 얼굴 경로의 꼬리 지연은 거의 그대로다. 다음 최적화 대상은 모델 자체보다 전처리·후처리와 작은 DNN 호출 사이의 동기화 구간이다.

CPU와 CUDA의 aggregate checksum은 각각 `2302.913`, `2302.991`로 실행 간에는 고정됐다. 이는 같은 코드 경로가 반복됐는지 확인하는 값이며 모델 정확도 평가는 아니다.

## 재현

```powershell
.\scripts\build.ps1 -EnableCuda
.\scripts\benchmark-dnn.ps1 `
    -Runs 5 `
    -Warmup 10 `
    -Iterations 100 `
    -Output benchmarks\results\dnn-cpu-vs-cuda-2026-08-28.csv
```

원시 측정값은 [`results/dnn-cpu-vs-cuda-2026-08-28.csv`](results/dnn-cpu-vs-cuda-2026-08-28.csv)에 있다. 각 행에는 모델 로드, 첫 추론, face/hand/cycle 분포, 처리량, 프로세스 CPU 시간, working set, GPU 샘플이 들어 있다.
